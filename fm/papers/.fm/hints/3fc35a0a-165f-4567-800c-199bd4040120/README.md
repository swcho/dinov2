# 쿼리 데이터셋 크기에 따른 retrieval 전략 차이

> **Q.** 쿼리 데이터셋 크기에 따른 retrieval 전략 차이는?
> **A.** 쿼리 데이터셋이 충분히 크면 각 쿼리 이미지마다 N개(보통 4개)의 최근접 이웃을 검색한다. 작으면 각 쿼리 이미지에 대응하는 클러스터에서 M개를 샘플링한다.

출처: DINOv2 논문(Oquab et al., 2023, arXiv 2304.07193) §3 "Data Processing" 중 *Self-supervised image retrieval* 단락, 그리고 부록 A.4 "Retrieval" 및 Table 15.

---

## 1. 이 질문이 놓인 맥락 — LVD-142M을 만드는 파이프라인

DINOv2는 라벨·텍스트 없이 이미지만으로 학습 데이터셋(LVD-142M)을 자동 구축한다. 핵심 아이디어는 **"작지만 잘 정제된(curated) 데이터셋을 쿼리로 삼아, 거대한 비정제(uncurated) 웹 이미지 풀(약 12억 장)에서 그와 닮은 이미지를 끌어와 데이터셋을 증강한다"**는 것이다.

![Fig.3 데이터 처리 파이프라인](fig-1.jpeg)

그림(Fig. 3)을 따라가면 세 단계가 보인다.

1. **Embedding** — 위쪽 회색 실린더(Uncurated Data)와 아래쪽 주황 실린더(Curated Data)의 이미지를 모두 같은 임베딩 공간에 매핑한다. 각 이미지 옆의 작은 격자가 임베딩 벡터다. 임베딩 모델은 ImageNet-22k로 자기지도 사전학습한 ViT-H/16이고, 거리 척도는 코사인 유사도다.
2. **Deduplication** — 비정제 데이터 안의 근접 중복(그림에서 빨간 X가 붙은 파스타 사진들)을 제거한다. 벤치마크의 test/val 세트와 겹치는 이미지도 여기서 걷어낸다.
3. **Retrieval** — 정제 데이터의 이미지(굵은 테두리로 강조된 파이 사진)를 **쿼리**로 삼아, 중복 제거된 비정제 풀에서 가까운 이미지를 가져와 오른쪽 "Augmented Curated Data"에 합친다. 카드가 묻는 "retrieval 전략"은 바로 이 세 번째 단계의 세부 규칙이다.

즉 **"쿼리 데이터셋"** = curated 소스(ImageNet-22k, ImageNet-1k, Google Landmarks, 각종 fine-grained/세분화/깊이 데이터셋 등)이고, retrieval 대상은 중복 제거 후 약 7.4억 장의 비정제 풀이다.

## 2. 두 가지 전략

논문은 쿼리 데이터셋의 **크기**에 따라 전략을 갈라 쓴다. 본문에서는 N, M이라는 기호로, 부록 A.4에서는 "sample-based"와 "cluster-based"라는 이름으로 부른다.

| | **큰 쿼리 데이터셋** | **작은 쿼리 데이터셋** |
|---|---|---|
| 부록 명칭 | sample-based retrieval | cluster-based retrieval |
| 기준 | 약 1M(100만) 장 이상 | 그 미만 |
| 방법 | 쿼리 이미지 **각각**에 대해 최근접 이웃 **N개** 검색 | 쿼리 이미지가 속한 **클러스터**에서 **M개** 샘플링 |
| 기본값 | N = 4 (ImageNet-22k, Google Landmarks v2)<br>N = 32 (ImageNet-1k, LVD-142M의 핵심으로 삼기 위해) | 비정제 풀을 k-means로 100,000개 클러스터로 나눔 → 쿼리 데이터셋 이미지가 **3장 이상** 들어간 클러스터마다 **10,000장** 추출 |
| 효과 | 데이터셋 크기를 대략 **N배**로 불림 | 결과가 매우 커질 수 있어 데이터셋당 **최대 1M장**으로 상한 |

### 2-1. Sample-based (쿼리 데이터셋이 클 때): 이미지마다 N개 최근접 이웃

- 쿼리 이미지가 이미 수백만 장이면, 이미지 하나하나에 대해 코사인 유사도 상위 N개를 가져오는 것만으로 충분히 다양하고 큰 증강 셋이 만들어진다.
- N=4를 고른 이유: 시각적으로 살펴보면 N을 4보다 훨씬 크게 잡아도 검색 품질은 좋아 보였지만, **collision**(서로 다른 여러 쿼리의 최근접 이웃으로 같은 이미지가 중복 검색되는 현상)이 늘어난다. N=4가 그 trade-off에서 적당했다.
- Table 15에서 확인되는 실제 수치:
  - ImageNet-22k 14,197,086장 → sample 검색 56,788,344장 (≈ 4배)
  - Google Landmarks v2 1,580,470장 → 6,321,880장 (≈ 4배)
  - ImageNet-1k 1,281,167장 → 40,997,344장 (≈ 32배, k=32 적용)

### 2-2. Cluster-based (쿼리 데이터셋이 작을 때): 클러스터에서 M개 샘플링

- Caltech-101(3,030장), Flowers-102(1,020장), Cityscapes(2,975장)처럼 수천 장짜리 데이터셋에 sample-based를 적용하면 4배로 불려도 1만 장 남짓이라 의미가 없다. 게다가 소수의 쿼리 주변만 좁게 훑어 다양성이 떨어진다.
- 그래서 먼저 비정제 풀 전체를 분산 k-means로 **100,000개 클러스터**로 나눈다. 각 클러스터는 서로 다른 유형의 시각 개념(concept)을 담는다고 가정한다.
- 쿼리 데이터셋의 이미지들이 어느 클러스터에 떨어지는지 보고, **3장 이상**이 들어간 클러스터(즉 그 데이터셋의 도메인을 대표한다고 볼 수 있는 클러스터)마다 **10,000장씩** 뽑는다. 이것이 카드의 "클러스터에서 M개 샘플링"이다.
- 이렇게 하면 데이터셋 규모와 무관하게 해당 도메인 전체를 넓게 커버하는 이미지가 확보된다. 다만 클러스터가 많이 걸리면 검색량이 수천만 장까지 커지므로(예: Food-101 → 21,670,000장, Met → 62,860,000장), 데이터셋 간 균형을 위해 **최대 1M장**으로 잘라 넣는다.

## 3. 왜 이렇게 나누는가 — 직관

- 목표는 "정제 데이터셋이 대표하는 **개념 분포**를 비정제 풀에서 재현하되, 몇 개의 지배적인 모드에 과적합되지 않게 **재균형(rebalance)**"하는 것이다.
- 큰 데이터셋은 이미 개념 분포를 촘촘히 덮고 있으므로 각 점 주변을 조금씩(N=4) 확장하는 것이 안전하다. 크게 확장하면 collision으로 중복이 늘고, 특정 이미지가 여러 쿼리에 끌려와 분포가 왜곡된다.
- 작은 데이터셋은 점이 너무 드물어 "점 주변"이 아니라 "점이 속한 영역(클러스터)"을 통째로 가져와야 도메인이 충분히 표현된다. 대신 상한(1M)을 두어 작은 데이터셋이 과도한 비중을 차지하지 않게 한다.
- 결과적으로 Table 15에서 cluster-based 행들의 Final 열이 대부분 정확히 1,000,000으로 맞춰져 있는 것을 볼 수 있다. 이것이 "작은 데이터셋도 각각 약 1M장씩 공평하게" 기여하도록 설계된 흔적이다.

---

## 4. 구현 메모

- 최근접 이웃 검색과 중복 제거는 모두 **Faiss** 라이브러리의 GPU 인덱스(inverted file index + product quantization)로 수행한다.
- V100-32GB 8장짜리 노드 20대에서 전체 파이프라인이 **2일 미만**에 끝나 LVD-142M이 만들어진다.

---

## 5. 한 줄 정리

> **쿼리 셋이 크면(≳1M장) 이미지별 최근접 이웃 N개(기본 4, ImageNet-1k는 32)를 붙이는 sample-based, 작으면 비정제 풀을 100k 클러스터로 나눈 뒤 쿼리가 3장 이상 걸린 클러스터마다 10k장씩(데이터셋당 최대 1M) 뽑는 cluster-based를 쓴다.**
